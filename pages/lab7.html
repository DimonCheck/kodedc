🌐 Настройка сети между двумя виртуальными машинами и решение проблемы пинга

Пошаговая инструкция по настройке внутренней сети между сервером и клиентом в VirtualBox, а также решение проблемы "сеть недоступна" при пинге.

📡 Схема сети:
Сервер: 2 сетевых адаптера (NAT + Внутренняя сеть) → IP: 192.168.1.7
Клиент: 1 сетевой адаптер (Внутренняя сеть) → IP: 192.168.1.8
Шлюз: 192.168.1.1
🖥️ Шаг 1: Настройка виртуальных машин в VirtualBox

Сервер (Server):

  • Адаптер 1: NAT (для выхода в интернет)
  • Адаптер 2: Внутренняя сеть (для связи с клиентом)

Клиент (Client):

  • Адаптер 1: Внутренняя сеть (для связи с сервером)
⚠️ Важно: Убедитесь, что на обеих машинах для «Внутренней сети» указано одинаковое имя сети (например, «intnet»).
🖥️ Шаг 2: Настройка сети на СЕРВЕРЕ

Откройте файл конфигурации сетевых интерфейсов:

sudo nano /etc/network/interfaces

Вставьте в файл следующие строки:

allow-hotplug eth0 iface eth0 inet dhcp auto eth1 iface eth1 inet static address 192.168.1.7 gateway 192.168.1.1 netmask 255.255.255.0 broadcast 192.168.1.255

Сохраните файл: Ctrl+X → Y → Enter

Активируйте новые настройки командой:

sudo service networking restart

Проверьте, появился ли IP-адрес 192.168.1.7:

ip addr show eth1
🔄 Рекомендация: После настройки желательно перезагрузить машину. Для этого нажмите на кнопку завершения работы и выберите «Перезагрузка».
🖥️ Шаг 3: Настройка сети на КЛИЕНТЕ

Откройте файл конфигурации сетевых интерфейсов:

sudo nano /etc/network/interfaces

Вставьте в файл следующие строки:

auto eth0 iface eth0 inet static address 192.168.1.8 gateway 192.168.1.1 netmask 255.255.255.0 broadcast 192.168.1.255

Сохраните файл: Ctrl+X → Y → Enter

Активируйте новые настройки командой:

sudo service networking restart

Проверьте, появился ли IP-адрес 192.168.1.8:

ip addr show eth0
🔄 Рекомендация: После настройки желательно перезагрузить машину. Для этого нажмите на кнопку завершения работы и выберите «Перезагрузка».
⚠️ Шаг 4: Решение проблемы пинга (сервер пингует, а клиент пишет "сеть недоступна")

Ошибка "сеть недоступна" на клиенте означает, что в его таблице маршрутизации нет правила, которое говорит: "чтобы попасть в любую другую сеть (например, 10.15.10.0/24), нужно отправлять трафик на сервер". Сейчас клиент умеет общаться только с устройствами в своей непосредственной сети (где находится сервер).

Чтобы это исправить, серверу нужно "разрешить" быть маршрутизатором, а клиенту — указать на сервер как на шлюз.

🔄 Решение: Настройка сервера как шлюза

1. Включение форвардинга (IP Forwarding) на сервере

По умолчанию Linux не пересылает пакеты из одной сети в другую. Это нужно включить.

Временное включение (до перезагрузки):

sudo sysctl -w net.ipv4.ip_forward=1

Постоянное включение (чтобы после перезагрузки работало):

Откройте файл /etc/sysctl.conf:

sudo nano /etc/sysctl.conf

Найдите строку #net.ipv4.ip_forward=1 и уберите символ # в начале, чтобы она выглядела так:

net.ipv4.ip_forward=1

Сохраните файл и примените изменения:

sudo sysctl -p

2. Настройка NAT (маскарадинга) на сервере

Сервер имеет два адаптера: NAT (смотрит в интернет/колледж) и внутренняя сеть (смотрит на клиента). Нужно сказать серверу: "Все, что приходит из внутренней сети и просится наружу, отправляй через интерфейс NAT, подменяя адрес отправителя своим". Это называется NAT (Network Address Translation) или маскарадинг.

Для этого используется iptables.

Выполните на сервере эти правила:

sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
sudo iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
sudo iptables -A FORWARD -i eth0 -o eth1 -j ACCEPT

3. Проверка и удаление правил iptables

Проверить наличие правил:

sudo iptables -L

Стереть все правила (если что-то напутали):

sudo iptables -F
🖥️ Настройка клиента

Клиенту нужно указать, что его шлюзом по умолчанию (gateway) является IP-адрес сервера во внутренней сети.

1. Узнайте IP сервера во внутренней сети

На сервере выполните команду и посмотрите адрес на интерфейсе eth1 (который смотрит во внутреннюю сеть):

ip a

Это будет адрес 192.168.1.7 (как мы настроили ранее).

2. Настройте маршрут на клиенте

Временный способ (для проверки):

На клиенте выполните команду, указав IP сервера:

sudo ip route add default via 192.168.1.7 dev eth0

(где 192.168.1.7 — это IP сервера, а eth0 — интерфейс клиента во внутренней сети)

✅ После этого пинг должен заработать!
✅ Шаг 5: Проверка связи между машинами

Пингуем и проверяем работу — должно пинговаться из сервера и из клиента.

С сервера (192.168.1.7):

ping 192.168.1.8
ping 10.15.10.1

С клиента (192.168.1.8):

ping 192.168.1.7
ping 10.15.10.1
✅ Если пинг проходит (есть ответы) — сеть настроена правильно!
