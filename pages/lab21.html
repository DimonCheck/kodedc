📊 Управление процессами, сервисами, таргетами и создание юнитов в systemd

Инструкция по работе с процессами, контрольными группами (cgroups), управлению сервисами, таргетами, питанием компьютера и созданию собственных юнитов в systemd.

📊 Процессы и контрольные группы (cgroups)
ps xaf
ps xawf -eo pid,user,cgroup,args
systemd-cgls

Каталоги в которых хранятся юниты:

ls -l /usr/lib/systemd/system/
ls -l /run/systemd/system/
ls -l /etc/systemd/system/

Выведите информацию о доступных типах юнитов:

systemctl -t help

Выведите информацию о состоянии всех юнитов:

systemctl status

Выведите информацию о состоянии всех юнитов (только сервисы):

systemctl --type=service

Выведите информацию о состоянии сервиса:

systemctl status apache2.service

Выведите информацию о состоянии сервиса другим способом:

systemctl is-active auditd.service
systemctl is-enabled auditd.service

Выведите информацию о зависимостях сервисов друг от друга:

systemctl list-dependencies --after auditd.service
systemctl list-dependencies --before auditd.service

Выведите информацию:

systemctl list-units --type=service

Измените команду:

systemctl list-units --type=service --all
systemctl list-units --type=socket --all

Выведите информацию о файлах юнитов и определите, какие сервисы разрешены (будут запускаться при загрузке) и какие запрещены:

systemctl list-unit-files --type=service

Выведите информацию о сервисах с ошибками:

systemctl --failed --type=service
⚙️ Управление сервисами
💡 ЕСЛИ НЕ ХОТИТЕ 1000000 РАЗ ВВОДИТЬ ПАРОЛИ — ПИШИТЕ ПЕРЕД КОМАНДОЙ SUDO!!!

Выполните запуск, останов, перезагрузку web-сервера Apache. Обратите внимание на изменение PID процессов после restart. Для контроля работы web-сервера Apache можно использовать команду curl 127.0.0.1.

systemctl status apache2.service
systemctl start apache2.service
systemctl status apache2.service
systemctl restart apache2.service
systemctl status apache2.service
systemctl stop apache2.service

Настройте запуск web-сервера Apache во время загрузки системы:

sudo systemctl enable apache2.service
systemctl status apache2.service
systemctl start apache2.service
systemctl status apache2.service
sudo systemctl disable apache2.service

Запретите запуск web-сервера Apache как во время загрузки системы, так и вручную (mask):

sudo systemctl mask apache2.service
sudo systemctl status apache2.service
sudo systemctl start apache2.service
sudo systemctl unmask apache2.service
🎯 Управление таргетами (targets)

Выведите информацию о загруженных активных target-юнитах:

systemctl list-units --type=target

Выведите информацию обо всех target-юнитах:

systemctl list-units --type=target --all

Выведите target-юнит по умолчанию:

systemctl get-default

Выведите ссылку на target-юнит по умолчанию:

ls -l /etc/systemd/system/default.target

Измените (установите другой) target-юнит по умолчанию:

systemctl set-default multi-user.target

Измените target-юнит в рамках текущей сессии:

⚠️ ПОСЛЕ ЭТОЙ КОМАНДЫ ВЫЛЕТАЕТ ИЗ ГРАФИЧЕСКОГО ИНТЕРФЕЙСА
systemctl isolate multi-user.target
Ctrl + Alt + Delete возвращают курсор мыши
💡 Пояснение: Команда systemctl isolate multi-user.target переключает систему в режим командной строки (мультипользовательский режим без графики).
graphical.target — полный графический интерфейс + командная строка.
multi-user.target — только командная строка (текстовый режим).
sudo systemctl isolate graphical.target

Переведите систему в rescue-режим (аналог однопользовательского режима):

systemctl --no-wall rescue

Переведите систему в emergency-режим:

systemctl --no-wall emergency
🔌 Управление работой системы и питанием компьютера
systemctl poweroff
systemctl halt
reboot
poweroff
systemctl --no-wall poweroff

Выгрузите систему и отключите питание компьютера в определенное время:

shutdown --poweroff чч:мм

Выгрузите систему без отключения питания через определенный промежуток времени:

shutdown --halt +минут

Перезагрузите систему:

systemctl --no-wall reboot

Приостановите работу системы (suspend):

systemctl suspend

Остановите систему (hibernate):

systemctl hibernate
📝 Создание собственных юнитов

Юнит-файл состоит из секций, включающих пары ключ-значение.

[Имя секции] Директива1=значение Директива2=значение

Секция [Unit]:

Description= Documentation= Requires= Wants=

Секция [Install]:

WantedBy= RequiredBy=

🧱 Что такое юнит? Юнит (unit) — это специальный конфигурационный файл, который описывает, как systemd должен управлять определённым ресурсом: службой (.service), таймером (.timer), точкой монтирования (.mount) и другими.

📝 Пошаговое руководство по созданию сервиса:

Шаг 1: Подготовьте исполняемый файл. Убедитесь, что ваш скрипт или программа находятся в известном месте и у него есть права на исполнение:

sudo chmod +x /usr/local/bin/myscript

Шаг 2: Создайте файл юнита. Юниты нужно создавать в директории /etc/systemd/system/. Назовите файл с расширением .service. Например, myapp.service:

sudo nano /etc/systemd/system/myapp.service

Шаг 3: Напишите конфигурацию юнита. Это минимально необходимый набор:

[Unit] Description=Краткое описание того, что делает ваша служба After=network.target [Service] Type=simple ExecStart=/usr/local/bin/myscript Restart=on-failure [Install] WantedBy=multi-user.target

Шаг 4: Сообщите systemd о новом юните:

sudo systemctl daemon-reload

Шаг 5: Запустите и добавьте в автозагрузку:

sudo systemctl start myapp.service
sudo systemctl enable myapp.service
systemctl status myapp.service

📂 Где хранятся юниты?

  • Системные юниты, созданные вами: /etc/systemd/system/
  • Системные временные юниты (до перезагрузки): /run/systemd/transient/
  • Пользовательские юниты: /run/user/ /systemd/transient/
